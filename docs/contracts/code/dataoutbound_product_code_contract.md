## Open review comments

- conn-imp-2: `api_token` is not a contract surface of the manual-trigger edge: the baseline (do-admin-api §10.3, orchestrator §3.1) carries the trigger as an HTTP 202 request whose authentication is handled by the JWT/RBAC boundary, not as a token field in the payload. Remove `api_token`; keep the trigger conf fields (target connection id, execution overrides, user context) as object-shaped fields.
- conn-imp-18: Description names 'Customer Staging Buckets', but this edge targets a separate bucket from conn-imp-9's staging write (bucket-15 vs bucket-8); per the baseline, EMR-side `push` records go to the Audit & Execution Log Store (audit_bucket), so `staging_s3_prefix`/`manifest_payload` are the wrong surface. Align the fields with the audit-store CloudEvent record shape (object with actor_id, timestamp_utc, event_type, execution_id, payload).
- conn-imp-8: `jdbc_connection_string` is a value-level/config detail that the baseline resolves at runtime via SSM/config (emr_do §14.1, dev §11.2 `RedshiftQueryConfig`), not a negotiated field of the read edge. Drop it; keep `extraction_query` (string) and add the structural watermark/mode job-argument object if needed.
